# Discovery index

The running catalogue of what we actually know, with how much to trust each item. Updated 2026-10-03.

Full detail lives in `research/`, which is raw agent output. This directory is the curated record. `design/` is what we concluded; `notes/00-premise.md` is the framing.

**Status key**

| Status | Meaning |
|---|---|
| **Verified** | I checked it myself against a primary source in this session. Quote it. |
| **Primary** | Read from a spec, repo, or vendor doc by a research agent, with the source cited. Strong, but I did not personally re-check. |
| **Weak negative** | "We found no X." No search engine was available, so absence of evidence is genuinely not evidence of absence. |
| **Unverified** | Flagged by the research as unconfirmed. Do not repeat in anything customer-facing. |
| **Blocked** | Not publicly knowable. Needs a cleared conversation or an NDA. |

## 4. Cross-domain transfer — the central problem

| # | Discovery | Status | Detail |
|---|---|---|---|
| 4.1 | **A diode preserves bytes; a guard may rewrite them.** Every problem descends from this. NCSC's import pattern puts transformation *before* the diode, on the low side. | **Primary** | `research/04` §1.1 |
| 4.2 | NCSC mandates that complex data types "should be transformed into simple, verifiable data types", and says software-only verification of complex parsers "is usually unachievable… so is not recommended". | **Primary** | `research/04` §1.3 |
| 4.3 | NCSC tells you to **assume the transformation engine is compromised**. So letting the guard re-sign its output converts an expected compromise into a total provenance bypass. | **Primary** | `research/04` §3.2(a) |
| 4.4 | `skopeo copy` documents the tension first-party: stripping platforms "invalidates the manifest list signature and changes the manifest list digest", and it **fails rather than silently re-signing**. The right design choice. | **Primary** | `research/04` §3.1 |
| 4.5 | **No published vendor guidance, standard or paper reconciles transform-based inspection with artefact signing.** The absence is the finding. | **Weak negative** | `research/04` §3.1, §11 |
| 4.6 | **The resolution: don't transform software, verify it.** Flat content-addressed blob store (`blobs/sha256/<hex>`, no nesting) plus one small strictly-schema'd signed manifest, so the guard does schema validation plus `name == sha256(content)`. A complete integrity check needing no understanding of OCI or ELF. | Conclusion | `design/01` §3 |
| 4.7 | **The accreditation argument:** CDR cannot disarm a container image, because the payload is executable code by design. Applying it to software destroys verifiability for close to zero security benefit. | Conclusion | `design/01` §3 |
| 4.8 | Iron Bank's cosign wrapper carries `use_alt_key`, documented inline as *"useful during re-signing or **cross IL**"*. The trusted-importer pattern, named in production code. The implementation itself is absent from the repo. | **Primary** | `research/04` §4.5 |
| 4.9 | The OCI **referrers API is a live call** with no file-based equivalent. A bundle must materialise the referrers graph into `sha256-<digest>` fallback tags at creation, or the high side holds signature bytes it cannot find. | **Primary** | `research/04` §2 |
| 4.10 | Sender-side state is the only workable delta mechanism: you cannot ask the high side what it has, so you *remember* what you sent. Zarf `--differential` and `oc-mirror` both work this way. | **Primary** | `research/04` §5 |
| 4.11 | TUF solves one-way key rotation — new root signed by a threshold of old root keys, verifier walks the chain offline. Ship `root.history/` every time. Bootstrap, however, is a trusted-*process* problem with no cryptographic solution. | **Primary** | `research/04` §9 |
| 4.12 | Debian `InRelease`, OSTree's signed summary and Zarf's `aggregateChecksum` are the same 25-year-old pattern: a detached signature over a small index that commits to payload by hash. Start there. | **Primary** | `research/04` §9 |
| 4.13 | **What a real guard accepts** — max file size, object count, whether a flat uncompressed tar reads as "simple verifiable" or as an archive needing recursive expansion, whether hash-only validation is acceptable, throughput, whether any ACK is permitted. **Six of seven unanswerable publicly.** | **Blocked** | `research/04` §11 |
| 4.14 | NCDSMO Raise the Bar requirements, the Cross Domain Baseline List and the LBSA methodology are controlled. The research's list of RTB themes is explicitly inferred. | **Blocked** | `research/04` §1.2 |

## 5. Supply-chain integrity — format-level

| # | Discovery | Status | Detail |
|---|---|---|---|
| 5.1 | **Hermeticity is not a SLSA Build L3 requirement.** The spec says so explicitly. L3 demands isolation and ephemerality. Conflating them is how teams conclude L3 is unreachable. | **Primary** | `research/03` §0 |
| 5.2 | SLSA **v1.0 is retired; v1.2 is current** (Nov 2025), adding the Source Track. CycloneDX is at **1.7**, published as **ECMA-424**; purl is **ECMA-427**. Most secondary literature is stale. | **Primary** | `research/03` §0 |
| 5.3 | NTIA's 2021 minimum elements are **superseded** by CISA's 2026 Minimum Elements. **SBOM Author Signature, SBOM Generation Context, and Component Hash are now minimum elements.** An unsigned SBOM no longer meets baseline. | **Primary** | `research/03` §1.1 |
| 5.4 | Generators disagree because they produce different *types* (Source / Build / Analyzed) and nobody labels them. Syft-on-an-image is Analyzed; Konflux's build task is Build. The 2026 Generation Context element fixes the labelling. | **Primary** | `research/03` §1.2 |
| 5.5 | SBOM conversion is lossy and **destroys document identity** — SPDX `documentNamespace` vs CycloneDX `serialNumber` means a converted document gets a newly minted identity. This is the loss that silently breaks attestation chains. | **Primary** | `research/03` §1.4 |
| 5.6 | **There is no registered in-toto predicate for VEX.** Verified against the full predicates directory. Every implementation mints its own. The largest standards gap in the stack. | **Primary** | `research/03` §4.2, §10 |
| 5.7 | SLSA's `externalParameters` are **untrusted** and `internalParameters` trusted; verifiers should **allowlist** not denylist. Also: accept only specific (signer, verifier) pairs, and give each build mode a distinct `builder.id`. | **Primary** | `research/03` §3.2 |
| 5.8 | The L3 sleeper requirement is **cache poisoning must be impossible** — output identical whether or not the cache is used. Most CI caches key on a tenant-supplied key and are therefore poisonable. Fixing that is a platform rewrite. | **Primary** | `research/03` §3.3 |
| 5.9 | Sigstore air-gap is solved by configuration: `cosign trusted-root create` / `signing-config create` produce static files. Fulcio has a first-class **`spiffe` issuer type**, so SPIRE→Fulcio inside an enclave needs **no code changes**. | **Primary** | `research/03` §3.4, §7 |
| 5.10 | Keyless yields a ~10-minute certificate, so verification in a different trust domain needs an inclusion proof or RFC 3161 timestamp. **Rule: keyless within a trust domain, long-lived HSM keys across trust domains.** | Conclusion | `design/01` §4 |
| 5.11 | **GUAC is not ready to be load-bearing.** v1.0/v1.1 shipped but the README still says "Beta", the recommended backend is non-persistent in-memory, and **both named graph databases are unsupported and incomplete**. Archivista is the smaller, closer alternative. | **Primary** | `research/03` §4.5 |
| 5.12 | **CPE false positives are the dominant cause of unusable vulnerability gates.** Rule: emit purl + CPE + hashes; match on purl; treat CPE-only matches as triage, not failures. | **Primary** | `research/03` §1.3, §4.4 |
| 5.13 | EPSS: base rate of exploitation is 2–3%, so **0.10 is roughly the 95th percentile**. Multiplying EPSS by CVSS "is never a good idea". KEV takes precedence when present. | **Primary** | `research/03` §4.3 |
| 5.14 | Conforma (formerly Enterprise Contract) is the closest thing to a complete open "opinionated glue". Its `trusted_task` rule — provenance that the build only ran approved steps — is the highest-value gate rule and the one most factories omit. Its `volatile_config` waivers **expire by construction** and warn before expiry. Steal both. | **Primary** | `research/03` §5.2 |
| 5.15 | Reproducibility is an achieved engineering result, not research: Debian 95.6% variance / 98.6% of attempted independent rebuilds; NixOS minimal ISO 96.59%. But there is **no documented operational answer to "a rebuild differed — now what"**. Build rebuilders; don't gate on it. | **Primary** | `research/03` §6.2, §10 |
| 5.16 | Hermeticity is a lock-file discipline problem, not a sandboxing one — and a hermetic build with prefetch yields a Build-type SBOM with real hashes. **Hermeticity and SBOM quality are the same problem wearing two hats.** | **Primary** | `research/03` §6.1 |
| 5.17 | SPDX 3.0/3.1 tooling is not ready: protobom has both **planned/planned** in each direction, `sigs.k8s.io/bom`'s SPDX3 output is experimental and not byte-reproducible. **Use SPDX 2.3.** | **Primary** | `research/03` §10 |
| 5.18 | C/C++ SBOM coverage: Syft and Trivy are **Conan-only**. cdxgen reads CMake/Meson/vcpkg/xmake but with no reliable version resolution outside `conan.lock`. No Fortran project type (Spack partially covers HPC). Nothing for embedded/RTOS. | **Primary** | `research/03` §2.1 |
