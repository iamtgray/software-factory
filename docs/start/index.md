# Getting Started

One argument, in two parts -- here's the problem, and here's the boundary that I think stops the whole idea collapsing.

1. **[The Problem](the-problem.md)** -- What a software factory is for, why the hard part turns out to be the evidence, and the mechanism that shows up in all four failures I've been able to document closely: evidence produced as a side effect, stored where nothing reads it, and never checked against the thing it describes.

2. **[Scope -- Three Layers, One Boundary](scope.md)** -- A platform consumed verbatim, a genuine product line, and application architecture ruled out of bounds because it's where two previous attempts died.

They're in that order because the boundary doesn't justify itself until the evidence problem is in view. If you already take that problem as read, the scope page is the one more likely to pick a fight with you: is application architecture really the place to stop?
